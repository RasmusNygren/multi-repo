# Agent guidance

## Documentation boundaries

- `README.md` is user-facing. Keep the opening path from installation to first
  successful synchronization short, and keep the complete configuration
  reference below it.
- `DEVELOPMENT.md` is for contributor setup, repository layout, and validation
  commands.
- Keep implementation rationale, architectural constraints, and future design
  context in this file rather than adding them to the README.
- If a configuration field or CLI option changes, update the code, tests,
  README reference, and relevant example together.

## Architecture

The Rust workspace has two crates:

- `multi-repo-cli` owns argument parsing, terminal progress, output formats,
  and process exit codes.
- `multi-repo-core` owns configuration loading, provider integrations,
  inventory state, Git operations, repository selection, search, and pruning.

Provider discovery produces repository specifications. Synchronization
reconciles those specifications with the SQLite inventory and then performs
bounded concurrent Git operations. A repository discovered through more than
one source is identified by its canonical remote and retains all source
associations.

## Invariants

- Treat user working trees as irreplaceable. Synchronization may fetch freely,
  but it may only fast-forward a clean working tree on its recorded default
  branch when the branch is strictly behind its remote.
- Never make `sync` delete a repository. Missing repositories become inactive;
  deletion is an explicit `prune` operation.
- Pruning must remain conservative. Keep repositories with tracked or
  non-ignored untracked changes, local-only commits, stashes, linked worktrees,
  invalid paths, or unverifiable state.
- New clones remain below the private state directory until an atomic rename
  makes a completed clone visible.
- Mutating operations share the workspace lock. Read-only search must remain
  available while synchronization runs.
- A failed provider discovery must not deactivate that provider's existing
  repositories. Reconcile only successful discovery results.
- Inline provider tokens are sensitive: redact them from debug output and
  never persist them in the inventory.
- Provider tokens authenticate REST discovery. Clone and fetch credentials are
  delegated to Git.
- Search stays in-process and parallel across repositories. It respects ignore
  files, includes hidden files, skips binary data, excludes `.git`, and does not
  follow symlinks.
- Preserve the grep-style exit contract: 0 for matches, 1 for no matches, and
  2 for errors.
- Keep configuration parsing strict with unknown-field rejection. Resolve
  relative paths from the file that declares them.

## Project direction

Planned layers include tracked-files-only search, isolated batch edits in Git
worktrees, resumable commit and publish runs, and GitHub and Bitbucket pull
request adapters.

A persistent search index is deferred until measurements on real repository
collections show that the index-free engine is insufficient.

The current discovery credential model is read-oriented. Before pull request
publishing is added, revisit the configuration model so fetch/discovery and
push/publishing credentials can be represented separately.

GitHub Actions must remain pinned to full commit hashes. Do not add a
pre-commit configuration until that pending project task is explicitly taken
up.
